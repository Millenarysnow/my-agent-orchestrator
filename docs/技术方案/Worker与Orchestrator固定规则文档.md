# Worker 与 Orchestrator 固定规则文档

本文记录项目根目录中的 `AO-WORKER.md` 和 `AO-ORCHESTRATOR.md` 如何成为各自会话角色的常驻指令。提示词组装入口见 `backend/internal/session_manager/manager.go` 与 `backend/internal/session_manager/prompt.go`；现有项目配置见 `backend/internal/domain/projectconfig.go`。

## 目标与非目标

**项目可以用两个固定名称的 Markdown 文档定义 Worker 和 Orchestrator 的角色规则。** AO 自动发现并注入对应文档，不要求用户配置路径，也不增加项目设置界面。

**规则按注册项目共享，并在系统提示词重建时生效。** 本功能不改变当前会话中的提示词，不实现热重载、按会话覆盖、按子仓库选择规则或 AO Cloud 控制面的规则同步。

**保留现有 `agentRules`、`agentRulesFile`、`orchestratorRules` 和 `orchestratorRulesFile` 配置。** 固定文档是无需配置的附加来源，不破坏已有项目的显式规则。

## 核心方案

**`session_manager` 在已有项目规则组装流程中，按会话角色额外读取项目根目录下的一个固定文件。** 这复用 AO 已有的服务端规则注入与提示词重建路径，不把约束托付给不同 agent 自己发现文件，也不在 renderer 保存第二份规则。

固定约定为：

- `AO-WORKER.md` 只注入 Worker 会话。
- `AO-ORCHESTRATOR.md` 只注入 Orchestrator 会话。

## 结构与依赖边界

**`Manager.buildSystemPrompt` 决定当前角色适用的固定文件，`buildProjectRules` 负责读取及合并规则文本。** 规则留在 backend 提示词边界内；CLI、HTTP、SQLite 和 OpenAPI 不增加新字段或新接口。

**文件位置固定在 daemon 注册项目的根路径。** 读取沿用当前 `AgentRulesFile` 的项目相对路径语义，避免依赖进程当前目录、agent 的运行目录或会话 worktree 是否已经准备完成。

**Standalone Worker 不扫描本机目录。** 它没有注册项目，不应意外继承启动 AO 的目录内容。

## 自动发现与组合

**固定文件存在时才读取，并合并进该角色已有的项目规则段。** 内容组合顺序为显式内联规则、显式配置的规则文件、固定角色文档；相同文件已由显式配置读取时只注入一次。这样保留现有顺序并避免固定文件被重复拼入。

**Worker 和 Orchestrator 始终按会话角色隔离读取。** Worker 不收到 Orchestrator 文档，Orchestrator 不收到 Worker 文档；否则角色边界会因仓库中恰好存在另一个文件而改变。

**固定文件不存在时静默跳过。** 两类角色规则都是可选项，空项目不需要创建占位文件，也不应因此阻止会话启动。

**存在但无法读取的文件仍使提示词构建失败。** 只有“文件不存在”代表可选项未配置；权限错误、目录误用等实际问题若被吞掉，会让用户以为约束已生效。

**显式配置的规则文件保持原有缺失即报错的行为。** 显式路径代表用户已经选择了一份必需文件，改变其失败语义会掩盖配置错误；静默跳过只适用于新约定的自动发现文件。

**文件在 Spawn、恢复或其他重建系统提示词的生命周期边界重新读取。** 修改文档会影响之后重建的提示词，但不会重写 agent 已收到的活动会话提示词。

## 必须守住的约束与陷阱

**不把固定文件名存入项目配置。** 若为了“启用”自动发现而调用 `ao project set-config`，就会重新引入用户要求移除的逐项目配置步骤。

**仅将 `fs.ErrNotExist` 视为可跳过。** 把所有读取错误都当作可选文件缺失，会静默丢掉用户期望生效的规则。

**固定路径必须经现有项目相对路径校验。** 未来若文件名改由外部输入、接受子路径或接受绝对路径，必须先重新定义读取边界；越界读取会让仓库规则机制访问项目以外的数据。

## 被否决的方案

**新增 Worker/Orchestrator 规则编辑界面被否决。** 规则以仓库内 Markdown 为唯一新增来源，避免用户界面配置与版本控制中的文档产生两份需要协调的内容。

**找不到固定文档就拒绝启动被否决。** 文档是可选约定，强制存在会让尚未采用该约定的项目无法创建会话。

## 未实现的部分与扩展准入

**多仓库工作区按每个子仓库分别加载规则不在本方案范围内。** 若以后增加此能力，必须先定义跨仓库合并顺序与同角色冲突语义，不能靠遍历结果的偶然顺序决定提示词。

**AO Cloud 控制面未纳入此次实现。** 扩展到云端前需先确认其项目文件访问边界和 worker/orchestrator 启动流程；本地 daemon 的路径语义不能直接套用到远程执行环境。
